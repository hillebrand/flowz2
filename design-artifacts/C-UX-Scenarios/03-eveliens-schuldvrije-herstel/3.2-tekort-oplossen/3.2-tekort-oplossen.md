## Overview

**Page Purpose:** Evelien ziet exact hoeveel tijd ze vandaag tekortkomt en lost dat op door escalerende aanbevelingen te accepteren of af te wijzen, tot het tekort volledig is opgelost.

**User Situation:** Komt net van 3.1-reden-kiezen — heeft "Te weinig tijd" gekozen en de beschikbare tijd voor vandaag bevestigd.

**Success Criteria:** Het tekort staat op 0, Evelien heeft daar zelf sturing aan gegeven (accepteren/afwijzen) zonder dat het als een verwijt voelde.

**Entry Points:**
- Vanaf 3.1-reden-kiezen: na "Bevestigen" (tekort + eerste aanbevelingen komen mee via de server-response)

**Exit Points:**
- Tekort bereikt 0 → 1.1-Home (enige exit-actie, scenario succes ✓). Er is bewust geen andere uitweg — uitstelgedrag zou het tekort alleen laten groeien.

## Layout Structure

Eén kolom: paginakop met geruststellende ondertitel, live tekort-teller, daaronder een dynamische set van maximaal 3 aanbeveling-kaarten.

```
┌────────────────────────────────────┐
│  Tekort oplossen                    │
│  Er is altijd een oplossing —       │
│  we lossen het samen op             │
│                                      │
│  Nog 20 min op te lossen            │
│                                      │
│  ┌────────────────────────────────┐ │
│  │ Uitstellen                      │ │
│  │ Geschiedenis — H5 lezen         │ │
│  │ uitgesteld naar morgen          │ │
│  │ +25 min      [Afwijzen][Accept.]│ │
│  └────────────────────────────────┘ │
│  ┌────────────────────────────────┐ │
│  │ Tijd verruimen                  │ │
│  │ Maandag van 2u naar 2,5u        │ │
│  │ +30 min      [Afwijzen][Accept.]│ │
│  └────────────────────────────────┘ │
│  ┌────────────────────────────────┐ │
│  │ Alleen het belangrijkste        │ │
│  │ Biologie — begrippen leren:     │ │
│  │ alleen het belangrijkste        │ │
│  │ +10 min      [Afwijzen][Accept.]│ │
│  └────────────────────────────────┘ │
└────────────────────────────────────┘
```

Geen "Niet doen"-kaart zichtbaar in dit voorbeeld — die verschijnt pas als de lichtere niveaus (incl. eerder afgewezen kaarten) niet meer volstaan.

## Data & API Requirements

### Data Sources

| Data Element | Source | Type | Required | Notes |
|--------------|--------|------|----------|-------|
| `shortfall_amount` | Meegegeven via de response van 3.1's `/api/day/shortfall` | duration | ja | Startwaarde voor `shortfall-remaining` |
| `recommendations` | Meegegeven via dezelfde response | array | ja | Eerste set aanbevelingen (max 3), al gesorteerd op niveau |

### API Endpoints

#### Aanbeveling accepteren

| Property | Value |
|----------|-------|
| Method | POST |
| Path | `/api/day/shortfall/recommendations/{id}/accept` |
| Purpose | Past de planning daadwerkelijk aan (taak uitstellen, tijd verruimen, verkorten, of laten vervallen) en retourneert het nieuwe tekort + evt. een vervangende aanbeveling |
| Auth | Required |
| Client-gedrag | Blokkerend — kaart toont Bezig-state tot de response binnen is |

#### Aanbeveling afwijzen

| Property | Value |
|----------|-------|
| Method | POST |
| Path | `/api/day/shortfall/recommendations/{id}/reject` |
| Purpose | Markeert de aanbeveling als afgewezen (blijft beschikbaar als laatste redmiddel) en retourneert een vervangende aanbeveling |
| Auth | Required |
| Client-gedrag | Blokkerend, maar zonder Bezig-state op de kaart (geen planningswijziging, dus vrijwel instant) |

## Technical Notes

- De garantie achter `shortfall-reassurance-text` ("altijd een oplossing") steunt volledig op het "Niet doen"-niveau: een taak volledig laten vervallen kan in theorie élk tekort dekken (mits er nog taken met lagere prioriteit over zijn). Dit lost het eerder gemarkeerde open punt over de engine-garantie op.
- Bewust géén paginabrede Laden/Fout-state: elke actie (accepteren/afwijzen) is per kaart, dus fouten en wachttijden blijven lokaal bij die kaart — vergelijkbaar met hoe 1.4 blokkerende states op paginaniveau vermeed.
- **Google Calendar write-sync:** bij het accepteren van een aanbeveling werkt Flowz ook het bijbehorende Google Calendar-event bij (verplaatst/verkort/verwijderd, afhankelijk van het niveau), indien Evelien een huiswerk-kleur heeft ingesteld — zie 4.1's Technical Notes.
