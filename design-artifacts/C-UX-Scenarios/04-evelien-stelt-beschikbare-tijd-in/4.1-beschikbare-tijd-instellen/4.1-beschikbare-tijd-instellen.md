## Overview

**Page Purpose:** Evelien stelt haar wekelijkse beschikbare tijd voor huiswerk in (ma–zo), met de mogelijkheid om voor specifieke dagen af te wijken van dat patroon.

**User Situation:** Aan het begin van een nieuwe periode, of wanneer haar wekelijkse rooster structureel verandert (bijv. een nieuwe sportclub), wil ze vastleggen hoeveel tijd ze per weekdag realistisch aan huiswerk kan besteden.

**Success Criteria:** Weekpatroon en eventuele dag-specifieke afwijkingen staan correct ingesteld; ze vertrouwt erop dat de motor daarmee rekent.

**Entry Points:**
- Hamburgermenu, vanaf elk scherm

**Exit Points:**
- Tikt op "← Terug" → vorige pagina (browser-history-gedrag). Wijzigingen zijn al direct verwerkt (geen aparte opslaan-actie), scenario succes ✓ zodra het patroon klopt.

## Layout Structure

Eén kolom: uitweg linksboven, paginakop, weekpatroon (7 rijen met +/-), daaronder een kalender voor dag-specifieke afwijkingen met een conditioneel paneel.

```
┌────────────────────────────────────┐
│  ← Terug                            │
│                                      │
│  Beschikbare tijd                   │
│                                      │
│  Weekpatroon                        │
│  Maandag      [-]  2u 0m  [+]       │
│  Dinsdag      [-]  1u 30m [+]       │
│  Woensdag     [-]  2u 0m  [+]       │
│  Donderdag    [-]  1u 30m [+]       │
│  Vrijdag      [-]  1u 0m  [+]       │
│  Zaterdag     [-]  0u 30m [+]       │
│  Zondag       [-]  1u 0m  [+]       │
│                                      │
│  Afwijkingen voor specifieke dagen  │
│  ┌──────────────────────────────┐   │
│  │       Augustus 2026           │   │
│  │  ma di wo do vr za zo         │   │
│  │  ...      12*  ...            │   │
│  └──────────────────────────────┘   │
│  ┌──────────────────────────────┐   │
│  │ Woensdag 12 augustus       ✕ │   │
│  │        [-]  1u 0m  [+]        │   │
│  └──────────────────────────────┘   │
└────────────────────────────────────┘
```

`*` markeert een dag met een actieve afwijking.

## Technical Notes

- Elke +/- klik is een losse, directe API-call (geen debounce/queueing) — bewuste keuze van Hillebrand, ondanks het risico op meer verkeer bij snel doorklikken.
- Het automatisch verdwijnen van een exceptie zodra de waarde het weekpatroon evenaart, gebeurt server-side (bij de PATCH-call) zodat client en server nooit uit sync raken.

### Google Calendar write-sync (huiswerk-kleur)

Zodra `avail-homework-color-select` een kleur heeft, wordt Flowz **actief schrijvend** in Google Calendar (voorheen alleen-lezen). Dit is een architectuur-relevante uitbreiding, hier vastgelegd als de UX-kant ervan:

- **Wanneer wordt een event aangemaakt/bijgewerkt:** telkens als de motor een sessie (opnieuw) inplant — dus bij het aanmaken van een taak (2.1), en bij elke herplanning (1.4, 3.2, 6.3, 7.1, 8.2). Zie de Technical Notes van die pagina's voor de exacte trigger.
- **Wat er in het event staat:** titel bijv. "Huiswerk: {vak} — {titel}", tijd = het geplande sessieslot, kleur = de gekozen huiswerk-kleur.
- **Bij verwijderen van een taak** (6.2): bijbehorende Calendar-events worden ook verwijderd.
- **Als Evelien het event zelf handmatig aanpast/verwijdert in Google Calendar:** Flowz detecteert dat niet actief. Bij de eerstvolgende (her)planning van die sessie overschrijft/hermaakt Flowz het event gewoon opnieuw (Flowz is bewust de bron van waarheid voor zíjn eigen events — eenvoudigste aanpak, geen conflict-detectie tussen handmatige en automatische wijzigingen in v1).
- **API-endpoints (indicatief, verder architectuurwerk):**
  - `POST /api/calendar/homework-events` — nieuw event aanmaken voor een geplande sessie
  - `PATCH /api/calendar/homework-events/{sessionId}` — bestaand event bijwerken (tijd verschoven)
  - `DELETE /api/calendar/homework-events/{sessionId}` — event verwijderen (taak verwijderd, of sessie vervalt door "Niet doen")
- **OAuth-scope:** vereist Calendar write-toegang, niet alleen lezen — zie 5.1-inlogscherm's Technical Notes.
